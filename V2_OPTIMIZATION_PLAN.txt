V2 Optimization Plan (Gemini cost + API-call reduction)
======================================================
Project: job-genie-new
Scope: Start with v2 “upload full flow” (resume upload -> parse -> embeddings -> recommendations).
Goal: Reduce Gemini token usage and avoid unnecessary Gemini calls while keeping output quality acceptable.


0) Baseline: confirm current Gemini call graph (v2)
---------------------------------------------------
Current “full flow” Gemini calls per upload:
- 1x Resume parsing:
  worker/celery_tasks/parse_resume_v2.py -> _call_gemini(file_text) -> client.models.generate_content(...)
- 1x Recommendations generation:
  worker/services/recommender_service.py -> generate_recommendations() -> self.model.generate_content(prompt)

Non-Gemini in that flow:
- Embeddings step uses local embedder (utils.local_embedder.get_embedding) and Qdrant.

Acceptance:
- After each optimization step, verify:
  - Total Gemini calls per v2 upload remains 2 (unless we intentionally merge/skip one)
  - Input tokens per call reduced
  - No breakage in v2 API endpoints used by frontend hooks


1) Biggest win first: reduce recommendation prompt size
------------------------------------------------------
Problem:
- Recommendations prompt likely includes up to 20 jobs with long “text/content”.
Approach:
- Ensure the prompt only includes compact fields per job:
  - title, company, location (if available), 5–10 key bullets, url
- Reduce candidate set before Gemini:
  - keep top_k smaller (e.g., 10) unless quality drops
  - optionally re-rank cheaply before sending to Gemini
Deliverables:
- Prompt builder adjusted so per-job payload is small and consistent.
- Token usage noticeably lower on recommendation call.


2) Reduce resume-parse input size (clean + cap PDF text)
-------------------------------------------------------
Problem:
- Full PDF-extracted text is sent to Gemini; PDFs often include duplicated headers/footers and noise.
Approach:
- Pre-clean extracted text:
  - normalize whitespace
  - remove repeated lines
  - drop obvious boilerplate sections
  - cap length with a safe heuristic (keep most informative sections)
- Keep output schema strict (JSON) to avoid verbose replies.
Deliverables:
- Parse prompt smaller + more stable JSON output parsing.


3) Avoid duplicate work: caching + idempotency
---------------------------------------------
Problem:
- Retrying uploads or re-uploading same resume can repeat costly calls.
Approach:
- Cache parse result by file hash / file_id.
- Cache recommendations by (resume_id or resume_embedding_version, job_index_version).
- Ensure celery tasks are idempotent and check DB before calling Gemini.
Deliverables:
- For identical inputs, Gemini calls are skipped and results reused.


4) Control on-demand Gemini spend (optional, after v2 core flow)
---------------------------------------------------------------
Features:
- WebSocket actions: explain match / resume advice
Problem:
- Users can trigger many repeated calls, often with verbose JSON payloads.
Approach:
- Send minimal resume subset + minimal job subset.
- Add server-side caching keyed by (resume_id, job_id, action).
- Add throttling/rate limiting.
Deliverables:
- Lower tokens per call and fewer duplicate calls per user session.


5) Job ingestion pipeline (separate from v2 user flow)
------------------------------------------------------
Celery: worker/celery_tasks/job_ingest.py -> JobProcessor -> JobLLMProcessor.parse_job_posting -> Gemini per job.
Problem:
- “Gemini per job” at ingestion time can be very expensive at scale.
Approach (later):
- Replace with deterministic extraction; use Gemini only for exceptions.
- Aggressive input trimming + caching by URL/content hash.


Implementation order (we will do this one by one)
-------------------------------------------------
Step A: Recommendation prompt shrink (v2 user-visible ROI highest)
Step B: Resume text cleaning/capping (reduce parse tokens)
Step C: Caching / idempotency in celery tasks (avoid repeated calls)
Step D: Optional: on-demand explain/suggest cost controls
Step E: Optional: ingestion pipeline Gemini reduction


How we’ll measure progress
-------------------------
- Log/measure prompt character length (proxy for tokens) before each Gemini call.
- Count Gemini invocations per upload_id (should be stable and skip when cached).
- Spot-check output quality for:
  - parsed resume JSON completeness
  - recommendation relevance
